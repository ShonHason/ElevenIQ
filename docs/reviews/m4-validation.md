- **Neighbours:** top 10 M4f neighbours on the full vector (partial rows included), excluding the same player; ties by the season key.

**Display rule for naming an axis end (not pre-registered).** An end is described by its loadings of at least 0.15 (unrounded). The value was chosen after seeing the loadings, to keep the CB lower end from being named by long pass completion (−0.11) against the user's decision. Rationale: a loading spread evenly over k metrics is 1/√k, 0.20–0.25 for these groups (k = 16–24 DNA metrics), so a smaller one does not define an end. It changes only page text, never a score. Each card says where the player leans on each axis (|z| < 0.5 near the middle, < 1.5 slight, else strong) and gives the three largest pushes as sentences (push = loading × (weighted value − group mean); all pushes sum to the score). Every number in a card names its source and is re-derived from the parquets after the page is written; a mismatch fails the run.

Facts are computed in Python (`spikes/m4g_compare.py`); the check re-derives them from `player_dna.parquet` and runs the page's own renderer in node for every ordered pair against the Python rendering.
