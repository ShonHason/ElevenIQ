# Plan 006 — Web v1: exported data contract + static React site (ADR 005)

**Status:** accepted (user, 2026-10-07; ADR 005 §11). UI libraries pending W2 verification. Nothing is implemented. **Starts after M4g6 sign-off** (decision 1a), as an early M9 before M5.

**Goal:** a shareable website showing "Find similar players", player pages and style maps for 2015/16, rendered by React from a versioned, schema-validated JSON export.
- Every number is computed in Python and traced.
- Data/ is never committed.
- The UI survives the remaining M4 chunks and the M7 API unchanged.

## Order and gates
- **Before W1:**
  - M4 signed off (M4g6 complete, including the plan 005 decision on one-member family weighting);
  - `docs/milestones.md` updated: web v1 becomes an early M9 before M5.
- **Before the first public deploy (W6):** the StatsBomb licence gate (ADR 005 §8, decision 4). This is blocking.
- **Every chunk ends with `/finish-chunk`.** From W2 on, it runs with the frontend tiers added in W2.

## W1 — Data contract and Python exporter (src/ + contract/ + spikes)
1. **Spike first.** `spikes/w1_export_reference.py` (no eleveniq imports) re-derives from the parquets:
   - the neighbour top-10 (from `m4f_dna_reference.pair_distance`);
   - the compare facts (`m4g_compare`);
   - the style-map points and pushes (`m4g_style_map` / `m4g_style_page`).

   It gets a `--check-output export/v1` mode that compares every exported value.
2. **Contract.** JSON Schemas in `contract/v1/` for: manifest, search index, player, compare, style map and labels (ADR 005 §2). Field names, units, rounding and format rules are written in the schema descriptions.
3. **Move logic into `src/`.**
   - `analytics/pairs.py`: top-k neighbours, ranks both ways with the 1e-12 tie rule, the 5 / 3 metric picks.
   - `analytics/style_map.py`: weighted PCA with the axis pins, pushes and lean.
   - `export/words.py`: `pct_words` with the neutral band, reason phrases, the withheld tags, labels incl. GROUP_LABELS and reason-code texts. Unknown codes raise.
   - Each with unit tests written from ADR 004 §11.5, §12, §13 and plan 005 M4g1 / M4g1b. The spikes stay as references.
4. **Exporter.** `src/eleveniq/export/build_export.py` (CLI `python -m eleveniq.export.build_export [--out export/v1]`):
   - refuses parquets whose sha256s differ from the registry and DNA stamps;
   - validates every file against the schema;
   - writes the manifest with per-file sha256;
   - output is byte-identical on re-run.
5. **Fixture export.** `--fixture` writes the fixed subset (≈ 25 rows: Kanté, Busquets, Carrick, Isco, Benzema, Messi, Neymar, Özil, Walcott, Stones, Morgan; a partial-DNA row, a mover, a below-gate row, a second-group row) to `tests/fixtures/web/`. It is committed. It regenerates only with `--update-fixture`, which prints a diff summary.
6. **Dependencies:** numpy and scikit-learn move to runtime in `pyproject.toml`; jsonschema is added to dev.
7. **Tests:** schema validation of the fixture and of a full export (integration), byte identity, and the reference check (integration).
8. **Reviews:**
   - code-reviewer;
   - qa-tester;
   - stats-reviewer: the reason picks and the moved style-map logic. These are output-equivalence checks; the method was reviewed in M4g0 / M4g1b.

2. **Contract types:** TS types generated from `contract/v1/`, committed, with a staleness test. The data module (`src/data/`) does fetch, Ajv validation (dev and test) and major-version refusal.
3. **Shell:**

6. **Process changes** (user approval in this chunk):

7. **UI libraries (ADR 005 §4, pending until this step passes):**

## W3 — Find similar players (landing page)
- **Search:** accent-insensitive matching on the exported search key; keyboard navigation of results; recent searches kept in `localStorage` (a convenience only).
- **Results:** the 10 neighbours with distance, rank and reasons; the provisional label (ADR 005 §3).
- **Compare panel:** from `compare/<group>.json`, loaded on demand. It has the headers, distance, ranks both ways, the 5 / 3 metric lists, the withheld tags, the Defending sentence and the map-distance warning. The panel enters and leaves along the same edge.
- **Playwright flow 1:** "Kante" → Kanté → 10 neighbours whose reasons equal the fixture → open compare with Busquets → distance and ranks equal the fixture; plus a keyboard-only run and axe.

## W4 — Player page
- **Identity and context.**
- **Radar:** shared-group rules from ADR 004 §12.9 (gaps for missing metrics, style axes uncoloured, `data-src` on every vertex); no animation.
- **Dimension scores:** with member counts and withheld status.
- **Percentile tables per family:** the §11.5 display rules (>99 / <1, status text for nulls, the ratio population sentence, team-influenced wording, global / local basis); tabular figures.
- **Signature traits:** shown as holder / non-holder.
- **Links:** to Similar players and the style-map point.
- **Playwright flow 3:** radar and percentile cells trace to the fixture; axe.

## W5 — Style maps
- **Parity with the M4g1 / M4g1b pages from `style-maps/<group>.json`:**
  - zoom, pan and pinch with a reset;
  - label culling by zoom;
  - hover cards (exported phrases and pushes);
  - search-to-zoom, with the cross-group message;
  - fine-role colours and toggles;
  - the explainer and legend with axis names, pins and notes;
  - compare mode (A then B, panel as in W3).
- **Later, from M6 (plan 005 backlog, "hybrid" players; not part of W5 until M6 pre-registers it):** a per-player 2D reconstruction-error flag, "not well represented on this map — see full profile", exported with the map data, never computed in JS.
- **Biplot toggle (user, 2026-10-09):** loading arrows per metric drawn from the map centre, labelled in plain language. Only metrics that pass the 0.15 loading display rule (plan 005 M4g1: |loading| ≥ 0.15, unrounded) get an arrow; arrows and labels come from exported loadings, never computed in JS.
- **Radar glyphs on zoom (user, 2026-10-09):** past a zoom level, each plotted player becomes a mini radar of their DNA percentiles instead of a dot. The values are the exported percentiles, drawn at their final value (no animation, per CLAUDE.md).
- **No t-SNE or UMAP (user, 2026-10-09):** the map stays a linear projection (PCA), because t-SNE / UMAP distances and axes are not interpretable.
- **Accessible alternative:** a sortable list view of the plotted players. Sorting uses exported ranks and orders, never a statistic computed in JS.
- **Playwright flow 2:** hover card text, search zoom, zoom in / out / reset, compare panel; reduced-motion and high-contrast emulation; axe.

## W6 — Deployment
- **Blocking checklist** (every box must be ticked before any public deploy; until then, private previews only):
  - [ ] The StatsBomb Public Data User Agreement (`LICENSE.pdf`) has been read in full.
  - [ ] Its terms are recorded in ADR 001: non-commercial use, attribution, the logo, and whether public hosting of derived per-player statistics and downloadable derived JSON is allowed.
  - [ ] The footer attribution and logo follow the agreement's wording.
  - [ ] Any term the site cannot meet goes back to the user, and the deploy stops.
- **Host:** Cloudflare Pages or Vercel, decided here (decision 3), on the host subdomain (decision 6).
- **Deploy:** option A (build locally, the user runs the CLI upload).
- **Scripts:**
  - `scripts/deploy` (or npm script) builds, copies `export/v1/`, uploads, then runs a smoke check. The smoke check confirms that the live `manifest.json` equals the local one, and fetches two player files and one compare file.
  - Claude prepares the commands; the user runs the upload (as with pushes).
- **Docs:** the about page and README section with the live URL, the methodology links and the attribution.

## How later chunks interact
- **M4g3–M4g6:**
  - re-run the exporter (new `registry_version` stamp) and re-check with `spikes/w1_export_reference.py --check-output`;
  - frontend and Playwright fixtures unchanged;
  - a new status code needs a `labels.json` text, or the export fails;
  - a changed axis loading that breaks a quoted value fails the export until the user re-checks the names.
  - **Mover verdicts (M4g3b, requirement):** if the contract or a page carries a mover verdict, it always shows its flags next to it: "underpowered at n", "borderline (seed-sensitive)", "PASS (below model range)". Never a bare "PASS" (user, 2026-10-08, from the M4g3b output review: 4 of the 9 PASS verdicts are underpowered, and `op_xg_assisted_p90` is also below model range). The exporter takes the flags from the registry (`Derivation.movers`), never recomputes them, and the contract has no verdict field without its flag fields.
- **M5 (similarity engine):** the neighbour section of the contract is replaced by the M5 output (contract minor version if the fields hold, major if they change). The "provisional" label goes.
- **M7 (API):** `frontend/src/data/` switches from static fetches to the API serving the same contract; pages unchanged.

## Out of scope for web v1
Gem Finder (M6), natural-language search (M8), accounts, analytics or tracking scripts, multi-season views, cross-source data, any server-side code.
